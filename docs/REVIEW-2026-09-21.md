## 2. What shipped: the ~4 h max-hold time stop

Pre-registered in the 09-17/09-18 reviews as fallback step 1 once the
falsification bar (0.75R-era P&L/trade ≤ −$0.40 at n ≥ 60) tripped. It
tripped 09-17 16:17 UTC and remains breached at n=90 (−$0.412), so this
session implemented it — the narrowest change, measured in isolation:

- `engine.py`: `MAX_HOLD_MINUTES = 240`. Any open trade older than that
  closes at market with `Exit_Reason TIME`, whatever the P&L.
- **Price exits take priority**: a simultaneous TP/SL wins. The stop only
  binds when the tick/candle touched neither level (verified both paths in
  smoke test K, including "armed-but-expired exits as TIME, not BE").
- **Both feed paths**: tick path (`check_position`) and MT5 candle path
  (`resolve_open_trade_on_candle`, at close). Wall-clock: across a market
  closure the trade exits on the first candle/tick back — the #95-style
  weekend gap now ends at the Sunday reopen instead of riding.
- **LIVE-mode caveat** (same as the BE ratchet): engine-side only.
  `run_live` never calls `check_position`, so a broker-side time stop is
  future work for any live pilot. No LIVE behaviour changes.

### TIME accounting convention (binding for future sessions)

- `time_exits` counter in `status.json`; `total_trades` includes TIME rows.
- **Decisive win rate excludes TIME** (like BE): TP/SL stay a pure signal
  read. All tools (`win_rate_report`, `analyze_losers`, `validate_gates`,
  `pathwalk_sims`) count TIME explicitly and print `/nTIME` only when > 0 —
  output on pre-TIME data is byte-identical to before.
- **Era P&L/trade includes every TIME dollar** — the falsification metric
  keeps booking reality.
- **SL streak / daily breaker ignore TIME** (like BE): a timeout is not a
  stop-out. Deliberate; revisit at the re-review if TIME losses cluster.
- `check_data.py` accepts the TIME domain and carries an early-fire
  tripwire (any TIME row held < 239 min warns).
